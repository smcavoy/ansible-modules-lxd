# The integration suite runs on LXD 6.10.2 (2026-11-27)

## What changed

- The sandbox image installs the LXD snap from the channel `6/candidate` (`DEFAULT_LXD_CHANNEL` in
  `ci/lxd_remote.py`). On 2026-11-27 the snap store had LXD 6.10.2 (`6.10.2-fa810fd`, revision 41487, released
  2026-11-26) only in `6/candidate`. `6/stable` had 6.10.1 (`6.10.1-f5c750d`, revision 41228).
- The new file `tests/lxd/sandbox/min-lxd-version` holds the minimum, `6.10.2`. It is part of the image recipe, so
  the image was built again.
- Guard 1, the image build: `tests/lxd/sandbox/prepare.sh` prints the version, revision and channel of the snap and
  stops the build when the version is older than the minimum.
- Guard 2, each run: `tests/lxd/lxdtest` reads the snap of every sandbox (the standalone slots, the members of the
  cluster, cluster-new, multi-cluster and MicroCloud fixtures), prints one line for each, and fails the run with
  exit code 2 when one is older. The run fails also when all tests passed on other slots. A version that has no
  number (an edge build) fails too.
- Unit tests: `tests/unit/lxdtest/test_lxd_version.py`.

## Result

- Full run on LXD 6.10.2: 78 of 78 passed (pass 78, fail 0, error 0, timeout 0, skip 0). All 13 sandboxes of the run
  printed `LXD 6.10.2-fa810fd, snap revision 41487, channel 6/candidate`.
- No module and no test was changed for 6.10.2. The suite found no difference in behaviour from 6.10.1.

## What this means

- The suite no longer tests LXD 6.10.1. `galaxy.yml`, the README and the module documentation still say
  "LXD 6.10.1 or newer". That text is not changed here. The owner decides if the minimum stays.
- The LXD of the test host itself is not part of this change. It runs 6.10.1; only the sandboxes run 6.10.2.
- Go back to `6/stable` when that channel has 6.10.2 or newer: change `DEFAULT_LXD_CHANNEL` in a pull request. No
  job does this by itself. When the change comes too early, guard 1 stops the image build with a clear message.
- Not checked: the LXD 6.10.2 release notes were not compared with the module code. The result above is what the
  suite shows.
